# Baseline производительности Huynity

Исходное состояние `1c2b89e`, 22 ноября 2026. Fedora 43 x86-64, Linux 7.3.3, Intel Core Ultra 5 125H, Intel Arc MTL, Mesa 25.3.6, GLX и SDL3/X11. Сборка Ninja в `build`, GCC 15.3.1, `RelWithDebInfo`, `-O2 -g -DNDEBUG -std=c++23`, адаптеры и тесты включены. Частота управляется системой, CPU закреплён за логическим ядром 2 при сравнительных прогонах. Целевой ориентир для 60 Гц — 16,67 мс на полный кадр.

54 теста CTest прошли на исходном коде. `integration.benchmarks` в одном диагностическом запуске показал 389 мкс для OpenGL с `glFinish`, 7970 мкс для CPU и 68 760 КиБ пикового RSS процесса. В OpenGL работают тени и небо, у текущего SoftwareRenderer этих эффектов нет. Этот запуск характеризует разные пути и не служит оценкой ускорения между ними.

## Тесселяция и подготовка снимка

Стенд создаёт 128 или 4096 статических коробок. Ортографическая камера видит все объекты. Сценарии различают отдельную геометрию каждого объекта и один общий меш. Измеряются полный обход `Scene::tessellation` и полный `prepareSnapshot` с разрушением снимка. Автоматически проверяются количество объектов, ресурсов, промахов и попаданий.

Пять парных прогонов в чередующемся порядке без параллельной сборки, 20 кадров прогрева и 101 измеренный кадр в каждом запуске. Таблица содержит медианы пяти результатов P50/P95/P99, мкс.

## OpenGL

Аппаратный рендеринг измерен со скрытым окном 1280×720, с 15 кадрами прогрева и 120 отсчётами на запуск. 3D-сцена содержит 64 коробки, тени 1024² и небо. В 2D-сцене 64 прямоугольника. CPU submit измеряет вызов `render()`. GPU `GL_TIME_ELAPSED` учитывает интервал исполнения с возможными простоями. `glFinish` в стенде опустошает очередь после каждой пробы. Времена исключают swap, захват кадра и RenderDoc.

Предварительный baseline из пяти запусков. Медианы P50/P95/P99, мс.

| Сцена | CPU submit | GPU elapsed | CPU с ожиданием GPU |
|---|---:|---:|---:|
| 3D | 0,087 / 0,149 / 0,179 | 0,236 / 0,285 / 0,286 | 0,634 / 1,033 / 1,438 |
| 2D | 0,154 / 0,313 / 0,357 | 0,029 / 0,032 / 0,033 | 0,358 / 0,643 / 1,110 |

RenderDoc 1.24 воспроизвёл оба кадра движка. В 3D насчитано 129 draws, из них 64 shadow, 64 world и один sky, плюс два clears. В 2D 64 draws и один clear. Отдельный счётчик вызовов даёт 536 и 194 запросов uniform locations соответственно. 3D-кеш исключает буферные загрузки на прогретом кадре. В 2D происходят 128 загрузок на 9728 байт и создаются 64 VAO. Средства захвата и реальные таймеры получены независимо от исходной телеметрии CTest.

В 3D CPU submit сократился примерно на 20%, в 2D — на 2,5%. Подтверждённого изменения GPU time нет. `glGetUniformLocation` в прогретом кадре — 0 в обоих сценариях после изменения. Draws, загрузки и остальные измеренные вызовы совпали. Захваты RGBA до и после совпали побайтово для обеих сцен.

## Копирование SceneView в смешанном кадре

Сцены из 192 и 1536 экземпляров используют два общих меша и три прохода World2D → World3D → HUD. У половины экземпляров есть дочерний объект. Пять парных прогонов, 20 прогревов и 101 отсчёт на запуск. Проверяются три прохода в том же порядке, число объектов, два ресурса и неизменное число тесселяций. Метрики аллокаций собраны отдельно перехватом обычных `new` и `new[]` во время подготовки и уничтожения снимка.

| Объектов | До, P50 / P95 / P99, мкс | После, P50 / P95 / P99, мкс | Аллокаций на кадр | Запрошено байт на кадр |
|---:|---:|---:|---:|---:|
| 192 | 36,09 / 39,68 / 42,18 | 19,62 / 19,95 / 24,54 | 348 → 57 | 347 680 → 98 848 |
| 1536 | 290,91 / 304,22 / 330,05 | 158,21 / 167,82 / 172,06 | 2382 → 75 | 2 732 832 → 742 176 |

Для 1536 экземпляров медиана снизилась на 46%, число аллокаций — на 97%. Это замер подготовки и уничтожения снимка. Бэкенд не запускался.

## Очистка CPU-кадра

Пустой снимок 1920×1080 в повторно используемом RGBA8 буфере, без показа. До исправления прогон с одним байтом padding на строку завершался под UBSan на первой невыровненной записи. После исправления все 101 измеренный кадр прошли под UBSan с `halt_on_error=1`. Тест отдельно контролирует четыре канала и padding.

На плотно упакованном буфере первая серия из семи парных прогонов дала медиану 1897,83 → 1877,05 мкс. Повторная серия из девяти дала 2043,66 / 2201,56 / 2277,41 → 2066,08 / 2222,41 / 2316,88 мкс по P50/P95/P99. Разница медиан меняет знак между сериями. Изменение принято по критерию корректности.

## Как воспроизвести

Запускать из корня рабочей копии. Для исходного варианта использовать неизменённую ревизию `1c2b89e` и те же файлы стендов. Если сборка уже существует, сохранить её опции. Новый каталог для сравнения должен иметь те же GCC и `RelWithDebInfo`.

```sh
HUYNITY_BUILD_DIR="$PWD/build"
cmake --build "$HUYNITY_BUILD_DIR" --target huynity_renderer huynity_objectlib huynity_benchmark_tests
ctest --test-dir "$HUYNITY_BUILD_DIR" -R '^integration.benchmarks$' --output-on-failure -V

includes=(-Iengine/core/include -Iengine/math/include -Iengine/objectlib/include
          -Iengine/image/include -Iengine/render_contracts/include -Iengine/renderer/include)
g++ -std=c++23 -O2 -g -DNDEBUG "${includes[@]}" tools/benchmarks/tessellation.cpp \
  "$HUYNITY_BUILD_DIR/engine/objectlib/libhuynity_objectlib.a" -o "$HUYNITY_BUILD_DIR/tessellation-bench"
g++ -std=c++23 -O2 -g -DNDEBUG "${includes[@]}" tools/benchmarks/scene_views.cpp \
  "$HUYNITY_BUILD_DIR/engine/objectlib/libhuynity_objectlib.a" -o "$HUYNITY_BUILD_DIR/scene-views-bench"
g++ -std=c++23 -O2 -g -DNDEBUG "${includes[@]}" tools/benchmarks/opengl.cpp \
  "$HUYNITY_BUILD_DIR/engine/renderer/libhuynity_renderer.a" \
  "$HUYNITY_BUILD_DIR/engine/objectlib/libhuynity_objectlib.a" \
  $(pkg-config --cflags --libs sdl3) -o "$HUYNITY_BUILD_DIR/opengl-bench"
g++ -std=c++23 -O2 -g -DNDEBUG "${includes[@]}" tools/benchmarks/software_clear.cpp \
  "$HUYNITY_BUILD_DIR/engine/renderer/libhuynity_renderer.a" -o "$HUYNITY_BUILD_DIR/software-clear-bench"

for run in 1 2 3 4 5; do
  taskset -c 2 "$HUYNITY_BUILD_DIR/tessellation-bench" > "$HUYNITY_BUILD_DIR/tess-$run.csv"
done
python3 tools/benchmarks/summary.py "$HUYNITY_BUILD_DIR"/tess-*.csv
for run in 1 2 3 4 5 6 7; do
  SDL_VIDEO_DRIVER=x11 taskset -c 2 "$HUYNITY_BUILD_DIR/opengl-bench" timing 3d \
    > "$HUYNITY_BUILD_DIR/gl-3d-$run.csv"
done
python3 tools/benchmarks/summary.py --opengl "$HUYNITY_BUILD_DIR"/gl-3d-*.csv
SDL_VIDEO_DRIVER=x11 "$HUYNITY_BUILD_DIR/opengl-bench" counts 2d
SDL_VIDEO_DRIVER=x11 "$HUYNITY_BUILD_DIR/opengl-bench" pixels 3d > "$HUYNITY_BUILD_DIR/3d.rgba"

taskset -c 2 perf stat -r 5 \
  -e cpu_core/cycles/u,cpu_core/instructions/u,cpu_core/cache-misses/u,cpu_core/branch-misses/u \
  "$HUYNITY_BUILD_DIR/tessellation-bench" >/dev/null
taskset -c 2 perf record --no-kernel-callchains --user-callchains \
  -e cpu_core/cycles/u -F 199 --call-graph dwarf,8192 -- "$HUYNITY_BUILD_DIR/tessellation-bench"
perf script | stackcollapse-perf.pl | flamegraph.pl > "$HUYNITY_BUILD_DIR/tessellation.svg"
valgrind --tool=dhat "$HUYNITY_BUILD_DIR/tessellation-bench"
```

На другой модели CPU подставить доступное ядро и PMU из `perf list`. На этой машине `perf` и Valgrind использовались из распакованных Fedora RPM. Запись Samply не проходит при текущем `perf_event_paranoid=2`. Чтение готовых профилей доступно. Серии CSV, RenderDoc-capture, DHAT и FlameGraph сохранены локально в `output/engine-audit/`.

Для подсчёта аллокаций пересобрать `scene-views-bench` с `-DHUYNITY_COUNT_ALLOCATIONS` и сравнить поля `new_calls` и `requested_bytes`. Для изоляции третьей итерации в исходном варианте сохранить индекс тесселяции из первой итерации.

`software-clear-bench` выводит 101 отсчёт после 20 кадров прогрева. Для замеров использовать плотно упакованный буфер и запуск без аргументов. Для проверки выравнивания пересобрать стенд и Renderer с ASan/UBSan, передать аргумент `odd` и включить `UBSAN_OPTIONS=halt_on_error=1`.
