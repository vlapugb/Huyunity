# Журнал рефакторинга

Аудит начат с `1c2b89e`. Исходный `git status` сохранён в `output/engine-audit/git-before.txt`. Существующие правки в `.archify`, `examples/game_scene/main.cpp`, локальных инструментах, диаграммах и OpenSpec сохранены.

## 1. Индекс кеша тесселяции

- В [TessellationCache](../engine/core/include/huynity/core/tessellation_cache.h) полный ключ включает идентичность исходной геометрии, версию, точные биты отклонения и лимит примитивов. Хеш заменяет линейное сканирование. Один элемент проверяется напрямую, чтобы сохранить стоимость попадания в распространённом сценарии с одним общим мешем.
- Ключ и значение удерживают владельцев исходной и тесселированной геометрии. Счётчики, коды ошибок и API сохранены. [Тесты](../engine/core/tests/tessellation_tests.cpp) проверяют раздельные объекты и версии, удержание владельца, NaN, ранее существовавший приоритет ошибки и отсутствие кеширования неуспешного запроса.
- Отдельный агент выполнил рефакторинг. Архитектурный аудитор независимо проверил равенство и хеш, времена жизни, ошибки и быстрый путь. Блокирующих замечаний нет.
- GCC RelWithDebInfo `build`, 54/54 CTest. Clang 21 ASan/UBSan `build-sanitize`, 54/54, с отключённой отдельной проверкой утечек драйвера. clang-tidy и Static Analyzer на целевых файлах не выдали диагностик проекта. OpenGL-тест исполнен с активным дисплеем.
- Подготовка 4096 уникальных объектов ускорилась с 3,45 до 1,20 мс по медиане повторной серии без фоновой сборки. Удержание старых записей остаётся задачей политики времени жизни. [Сравнение и профиль](PERFORMANCE_BASELINE.md)

## 2. Uniform locations OpenGL

- В [GlRenderer](../engine/renderer/src/gl_renderer.cpp) 35 locations привязаны к своим четырём слинкованным программам. Материальные locations переиспользуют общий тип. Сохранены порядок, типы и значения вызовов `glUniform*`, включая поведение для location `-1`.
- [GLX-тесты](../engine/renderer/tests/opengl_tests.cpp) учитывают запросы через реальный resolver. Проверяются запросы при создании и их отсутствие в режимах World3D, HUD, sky и shadow. Повторный теневой кадр также проверяется.
- Независимое ревью выполнил графический аудитор. Блокирующих замечаний нет. Инициализация программы при неудачной линковке остаётся отдельной проблемой.
- В обоих деревьях сборки 54/54 CTest. Clang Static Analyzer и clang-tidy на файлах итерации не выдали диагностик проекта. Побайтовое сравнение двух RGBA-кадров прошло.
- 536 → 0 запросов locations на 3D-кадр, 194 → 0 на 2D. Медиана CPU submit 3D снизилась с 87,7 до 70,5 мкс. [Парные измерения и GPU-таймеры](PERFORMANCE_BASELINE.md)

## 3. Подготовка draw lists без копий SceneView

- [Scene](../engine/core/include/huynity/core/scene.h) предоставляет `RenderPreparation` два закрытых read-only span идентификаторов и экземпляров в том же плотном порядке. Публичный владеющий `SceneView` сохраняет текущий контракт.
- [World3D, World2D и HUD](../engine/core/include/huynity/core/render_preparation.h) в том же порядке проверяют видимость, трансформации и тесселяцию. Получение тесселяции меняет флаг в экземпляре и отдельный кеш. Оно не меняет состав плотного хранилища.
- [Регрессионный тест HUD](../engine/core/tests/hud_tests.cpp) проверяет уплотнение после удаления, стабильный порядок равных ключей, связь с геометрией, независимость прежнего владеющего view и отсутствие обновления bounds для HUD.
- Инженер CPU независимо проверил времена жизни span, порядок проходов и сохранение ошибок. Блокирующих замечаний нет.
- В обоих деревьях сборки 54/54 CTest. clang-tidy и Clang Static Analyzer не выдали замечаний по изменённым участкам.
- 1536 экземпляров: 290,91 → 158,21 мкс и 2382 → 75 вызовов `new` на прогретую подготовку снимка. [Стенд и исходные условия](PERFORMANCE_BASELINE.md)

## 4. RGBA-очистка с произвольным stride

- [SoftwareRenderer](../engine/renderer/src/software_renderer.cpp) копирует RGBA как четыре байта и не требует выравнивания строк. Копирование ограничено шириной изображения.
- [Тест](../engine/renderer/tests/software_renderer_tests.cpp) использует ширину 3, stride 13 и sentinel в padding четырёх строк. Проверяются все каналы и сохранение sentinel.
- До исправления Clang UBSan остановил стенд на невыровненной записи. После исправления тот же неплотный буфер прошёл 20 прогревочных и 101 измеренный кадр. Независимое ревью проверило выравнивание и границы записи. Блокирующих замечаний нет.
- На плотно упакованном буфере 1920×1080 медиана около 2 мс в обоих вариантах. [Две парные серии](PERFORMANCE_BASELINE.md)

## Итоговые проверки

- GCC в `build`, 54/54 CTest. `renderer.opengl` действительно отработал под GLX. Полную сборку рабочей копии блокирует ранее внесённый вызов `onUpчdate` в `game_scene`. Версия примера из HEAD собрана отдельно с текущими библиотеками.
- Clang 21 в `build-sanitize`, 54/54 CTest с ASan и UBSan с остановкой при первой ошибке. Отдельный детектор утечек ASan отключён в общем наборе. DHAT проверил стенд тесселяции. Изменения не добавляют межпоточной работы.
- Для пула ресурсов, индексов в byte span, жизненного цикла GL и VAO/VBO в World2D оставлены воспроизводимые находки и критерии в [аудите](ENGINE_AUDIT.md). [План Vulkan](VULKAN_MIGRATION.md) сохраняет последовательность верификации OpenGL и будущего бэкенда.
