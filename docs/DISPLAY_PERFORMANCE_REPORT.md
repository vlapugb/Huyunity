# Производительность OpenGL и дисплеи

Замеры выполнены на Fedora 43, Intel Core Ultra 5 125H и Intel Arc MTL с Mesa 25.3.6. Основная сессия GNOME Wayland, X11-путь SDL работает через XWayland. Сборка `build-stress-release` использует GCC 15.3, C++23 и `-O3 -g -DNDEBUG`. Физическая конфигурация дисплеев оставалась неизменной.

| Дисплей | Нативный режим | Масштаб GNOME | Роль |
|---|---:|---:|---|
| DP-5 | 2560×1440, 143,98 Гц | 100% | Основной |
| DP-6 | 2560×1440, 74,92 Гц | 100% | Дополнительный |
| eDP-1 | 2880×1800, 120 Гц | ≈167% | Встроенный |

Режимы и масштаб получены из текущего состояния Mutter. SDL в XWayland видит виртуальные размеры 5120×2880 для внешних дисплеев и 3456×2160 для встроенного. В нативном Wayland SDL сообщает виртуальный режим встроенного дисплея 1728×1080 при 120 Гц.

## Разрешение кадрового буфера

`engine_resolution_benchmark display 3d` создаёт настоящее окно SDL и аппаратный GL-контекст. Сцена содержит 64 коробки, 64 теневых draws и один draw неба, всего 129 draws. Снимок сцены фиксирован. Замер включает отправку GL-команд и `SDL_GL_SwapWindow`. GPU-таймеры читаются после серии, `glFinish` применяется на границах серии. Запрошен и подтверждён swap interval 0. Диспетчер окон и драйвер всё равно могут задерживать swap. Число кадров показывает пропускную способность цикла приложения, физическая частота презентации ограничена дисплеем и композитором.

В каждой строке медиана трёх запусков по 180 кадров после 15 кадров прогрева. Фактический размер OpenGL drawable подтвердился для всех пяти размеров. CPU submit и GPU elapsed — медианы отдельно измеренных времён. FPS учитывает завершение команд после последнего кадра. По отдельным кадрам измеряются render и swap, без обработки событий. CPU% нормирован на одно ядро процесса. GPU% учитывает время render engine DRM-клиентов процесса из `/proc/self/fdinfo`, включая работу драйвера для этого клиента. Стенд различает клиентов разных PCI-устройств и выводит `unavailable` при отсутствии подходящих счётчиков. RSS/PSS сняты после серии.

RenderDoc MCP воспроизвёл кадр 1280×720 той же сцены и подтвердил 129 draws и два clears. В захвате три текстуры на 11,03 МиБ и 128 буферов на 0,02 МиБ. Это объём ресурсов кадра по данным захвата. Отдельный инструментированный прогон подтвердил 129 draws во всех семи размерах на обоих бэкендах. Исходные результаты сохранены в `output/stress-audit/renderdoc-replay.log` и `output/stress-audit/draws-resolution.txt`.

## Перенос окна и VSync

Нативный стенд вызывал `Engine::step`, проверял реальный дисплей окна, размер drawable, GL viewport, размеры захвата и сохранение контекста. SDL подтвердил swap interval 1. Оконные и полноэкранные этапы содержат по 90 измеренных кадров. Полноэкранный режим использовал текущий режим рабочего стола.

| SDL / дисплей | Окно 800×600, FPS / P95 / P99, мс | Fullscreen drawable | Fullscreen, FPS / P95 / P99, мс |
|---|---:|---:|---:|
| Wayland / DP-5 | 142,69 / 9,32 / 13,36 | 2560×1440 | 131,48 / 11,42 / 25,95 |
| XWayland / DP-5 | 133,53 / 11,75 / 16,44 | 5120×2880 | 92,60 / 18,75 / 20,11 |
| XWayland / DP-6 | 74,42 / 15,64 / 19,11 | 5120×2880 | 73,22 / 18,38 / 28,25 |
| XWayland / eDP-1 | 117,25 / 9,98 / 16,95 | 3456×2160 | 121,26 / 9,13 / 9,98 |

На XWayland одно окно дошло до всех трёх дисплеев и вернулось из fullscreen. Частота оконных кадров менялась при переносе вместе с частотой дисплея. В Wayland композитор отклонил позиционирование обычного SDL-окна на двух дополнительных дисплеях. В нативном окне работа с разным масштабом проверена отдельной последовательностью resize, где композитор сам менял размещение. Замеров влияния числа подключённых дисплеев в этих данных нет.

Запросы всех пяти размеров, 1371×793 и 1×1, а также 12 повторных resize прошли на обоих бэкендах с правильным viewport. В Wayland при масштабе ≈167% запрос 1920×1080 дал drawable 3200×1800, 2560×1440 — 4267×2400, 3440×1440 — 5733×2400, 3840×2160 — 6400×3600. В XWayland запросы 1371×793 и 1×1 округлились до 1372×794 и 2×2. Эти прогоны используют high-DPI окно `Engine`. Таблица выше для пяти размеров использует отдельный стенд с точным размером drawable.

Для нестандартного и минимального окна стенд `Engine` собрал по 90 кадров с VSync. Здесь измерено полное время `Engine::step` и загрузка CPU.

## Воспроизведение

```sh
HUYNITY_BUILD_DIR="$PWD/build-stress-release"
cmake -S . -B "$HUYNITY_BUILD_DIR" -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_FLAGS_RELEASE='-O3 -g -DNDEBUG' -DBUILD_TESTING=ON \
  -DHUYNITY_BUILD_ADAPTERS=ON -DHUYNITY_BUILD_EXAMPLES=OFF
cmake --build "$HUYNITY_BUILD_DIR" --parallel 3
SDL_VIDEO_DRIVER=wayland taskset -c 2-7 "$HUYNITY_BUILD_DIR/tests/integration/engine_resolution_benchmark" \
  display 3d 3840 2160 180 > frame.csv 2> frame.log
python3 tools/benchmarks/display_summary.py --output summary.csv frame.csv
SDL_VIDEO_DRIVER=x11 "$HUYNITY_BUILD_DIR/tests/integration/engine_monitor_test" --inventory
```

Сырые результаты находятся в `output/stress-audit`. Две разные дисплейные подсистемы использовали три активных дисплея. Сравнение по числу подключённых мониторов требует отдельной серии на неизменных настройках нагрузки и новых разрешённых физических конфигурациях.
